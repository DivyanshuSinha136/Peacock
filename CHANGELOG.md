# Peacock OS - changelog and detailed notes

> This file keeps the long-form notes of every release (the original README). The overview is in [README.md](README.md).


**A small bootable GUI operating system written in KingCobra.**  Author: Divyanshu Sinha · MIT License

Windows use a flat, modern look with frosted-glass blur (title bars, taskbar, Start menu and the Terminal blur whatever is behind them; `kernel/glass.kc`): rounded title bars with round minimise/close buttons, soft shadows, a rounded taskbar and Start menu.

| Part | Written in | How it is built |
|---|---|---|
| Bootloader (`boot/boot.kc`, `boot/x86.kc`) | **KingCobra** | run by the KingCobra interpreter; emits the MBR + stage 2 machine code. No NASM, no KASM |
| Kernel, drivers, window manager, apps (`kernel/*.kc`) | **KingCobra** | `kcc --target kcos` → flat binary. No C, no C libraries |
| Disk image builder (`tools/mkimage.kc`) | KingCobra | run by the interpreter |

Output: **`peacock.img`** (raw 8 MiB BIOS disk image; contains the KingCobra source bundle for the terminal's `install`).

```bash
# from the KingCobra repository root:   make            (builds ./kingcobra)
cp -r <this folder> peacock && cd peacock
make                 # -> peacock.img
make run             # qemu-system-x86_64 -drive format=raw,file=peacock.img -m 128 -vga std -nic user,model=rtl8139
make run-serial      # headless, kernel log on your terminal
make test            # QEMU boot test (serial log + screendump + keyboard)   needs qemu + python3
```
In the QEMU window click once to grab the mouse (release with Ctrl+Alt+G).

## Resolution

The boot stage now asks the BIOS for a 1024x768 .. 1280x1200 mode first (1280x800, 1024x768, 1280x1024 ... all 24/32-bit linear-framebuffer modes are tried; wider modes are skipped because the kernel supports up to 1280 wide) and only falls back to 800x600 / 640x480 when none exists. `make boot-sim` checks the selection logic.

## Themes

Nine desktop themes built from the supplied pictures (`assets/themes/theme1..9.jpg`): Misty Forest, Violet Plume, Aqua Crest, Marigold, Rose Plume (default), Moon Mandala, Flute & Eye, Gold Line, Om Glow (the last two are white line art on black). Each has a wallpaper (the picture on a blurred, darkened backdrop of its own colours) and matching accent colours for the taskbar, start menu, window badges and selections.
Pick one in the **Appearance** app (desktop icon / start menu / `open appearance`) or with `theme N` (1-9) in the terminal; the choice is saved in `/etc/theme` and restored at boot. `tools/mkthemes.py` prepares the pictures (`make` runs it); they live in the disk image after the install bundle (the bundle limit is now 4 MiB; wallpapers are 640x400). `make host-test-theme` tests the app, the command and the wallpapers.

## Boot splash

While the kernel starts (file system, disk, saved files, apps, network) a white splash shows the peacock logo (`assets/peacock-logo.jpg`, scaled to 160x280 by `tools/mklogo.py` and stored in the disk image), a rotating dot ring, a progress bar and a status line, animated from the 100 Hz timer (`kernel/splash.kc`); it stays at least 1.6 s.

## What you get
A 800×600 (or the first VBE mode the BIOS offers) true-colour desktop: peacock-feather wallpaper, desktop icons (double-click),
a taskbar with a Start menu, window buttons and a clock, draggable overlapping windows with minimise/close, a software mouse
cursor, and thirteen apps:

* **Terminal** – `help ls cd cat mkdir touch rm echo > file sync mem cpu date uptime neofetch open reboot poweroff` on the in-memory filesystem (KCFS; `sync` saves it to the disk image)
* **Notes** – text editor, Ctrl+S saves `/home/notes.txt`
* **Paint** – 16 colours, 4 brush sizes, clear
* **Calculator** – fixed-point (3 decimals), mouse or keyboard
* **System Info** – CPU (CPUID), RAM, heap, display, uptime
* **Files** – file manager for KCFS: browse folders, text preview, New dir / New file / Delete (Up/Down, Enter, Backspace, Del)
* **Calendar** – month view from the RTC, today highlighted, day selection (arrows = month/year, Home = today)
* **Clock** – analog + digital clock with date, and a stopwatch (Space start/stop, R reset)
* **Snake** – arrow keys/WASD, speeds up as you grow, Space pauses, Enter restarts
* **Minesweeper** – 9x9, 12x10, 16x12; left click opens, right click (or the Flag button) flags; first click is always safe
* **Monitor** – uptime, frames/s, heap/RAM/filesystem bars, heap history graph, window list with an End button
* **Taskbar tabs** – every open window is a tab at the bottom with an app badge; click to focus or minimise, the x (on the active or hovered tab) or a right-click closes it, "+" opens the app menu
* **Pointers** – anti-aliased arrow, hand (over clickable things and links) and text beam (over text areas), generated by `tools/gencursor.py`
* **Browser** – web browser: HTTP over the network (RTL8139 driver, ARP/IPv4/DHCP/DNS/TCP written in KingCobra), an HTML renderer (headings, paragraphs, lists, links, bold/italic/code/pre, blockquotes, tables flattened to rows, `<img>` alt text, entities, UTF-8 to ASCII), redirects, history, scrolling, `file://` and `about:` pages. **No HTTPS/TLS, no CSS, JavaScript or images.**

### App Builder
Open **App Builder** from the desktop or Start menu and design a window app with the mouse: add labels, buttons, text boxes, checkboxes, progress bars and
panels, drag them around, resize them from the corner, change text and colours. Buttons, checkboxes and text boxes (on Enter) run an action:
set text, append text, add / multiply a number, **calculate** (`1+2` = widget #1 plus widget #2; `+ - * / %`), copy a text box into a label,
clear, show/hide a widget, change a colour, open another Peacock app, beep, close the window.
Editing aids: **Undo** (Ctrl+Z, again = redo), duplicate (Ctrl+D), bring to front / send to back, snap-to-grid, Tab to select the next widget,
arrow-key nudging, large text for labels, "starts hidden", delete apps from the Open list, Ctrl+S to save.
**Run >** saves the app to `/apps/NAME.pea` and opens it in its own window; `run NAME` in the terminal or a double-click in Files starts it later.
`.pea` files are plain text (see `kernel/builder.kc`), so they can be edited in Notes or shared. Six examples ship in `/apps`
(counter, adder, greeter, keypad, progress, launcher; regenerate with `tools/gensamples.py`).
Limits: 32 widgets per app, one running app window at a time, apps are built from the widgets above (no custom code); reordering renumbers widget
references except inside Calculate formulas. Use **Sync** to keep saved apps after a reboot.

### Installing the KingCobra source
The build packs the whole KingCobra repository into the disk image (`BUNDLE=0` to skip). In the Terminal:
```
install -l                 # list what the bundle holds
install                    # unpack to /usr/src/kingcobra  (add a path to unpack elsewhere)
sync                       # persist the filesystem to the disk
cd /usr/src/kingcobra ; tree -d ; grep -n -r "fn main" kcc ; edit kcc/src/main.kc
```
Terminal additions: `cp mv rm -r head tail wc grep find tree du df edit`, Tab completion, scrollback (PgUp/PgDn), Ctrl+C for running jobs.
The installed source is stored and can be read/edited (Notes/`edit`, Files, Browser `file://`); Peacock cannot compile or run KingCobra programs itself.

### Network

## How it boots
1. BIOS loads the MBR (stage 1, 512 B) → it loads stage 2 (2 KiB) with INT 13h extensions.
2. Stage 2 (real mode): A20, E820 memory map, **VBE**: first usable linear-framebuffer mode
   from `0x143, 0x141, 0x115, 0x118, 0x144, 0x112 …` (modes smaller than 640x480 are skipped: QEMU’s 0x141 is 640x400) (32 or 24 bpp), then protected mode → page tables (4 GiB identity map, 2 MiB pages,
   ≥3 GiB uncached) → **loads the kernel by ATA PIO (LBA28, primary master, 128 sectors per command) to `0x200000`** → long mode → `jmp 0x200000`.
   BIOS INT 13h can't reach above 1 MiB, so the kernel is read in protected mode; the image limit is **64 MiB** (was 448 KiB).
   The disk layout follows the kernel size: KCFS store at the first 1024-sector boundary after the kernel, boot logo 7168 sectors after that, install bundle at 7680.
3. The kernel (`kmain`): GDT/TSS/IDT, PIC, PIT 100 Hz, PS/2 keyboard + mouse, physical memory manager + heap, framebuffer,
   KCFS, then the desktop loop (`ui_frame` + `hlt`).  A fault shows a red panic screen (and goes to COM1).

Hand-over contract (`boot/boot.kc` header): `0x500` magic `PEAC`, E820 count, boot drive, kernel sectors; E820 entries from `0x510`;
`0x6F0` VBE mode; `0x700` the VBE ModeInfoBlock (pitch, width, height, bpp, framebuffer address).

### About "bootloader in KingCobra"
`kcc` emits 64-bit code only, and a BIOS boot stage must start in 16-bit real mode and pass through 32-bit protected mode.
So the bootloader is a KingCobra *program* (`boot/boot.kc`) that calls an instruction emitter written in KingCobra
(`boot/x86.kc`: `mov_ri`, `jmp_far`, `lgdt_m` …, one function per instruction, labels resolved in `finish()`).  There is no assembler
syntax and no external tool involved; the emitter is not KASM.  `make boot-selftest` proves the emitter: it re-creates the
NASM-assembled KCOS boot stage and compares it **byte for byte** (2560 bytes identical).

## Limits
Single CPU, ring 0 only (apps are compiled into the kernel, no user mode/processes), PS/2 keyboard and mouse only, RTL8139 network only (HTTP, no TLS), no sound,
ATA PIO disk, filesystem is a flat dump of an in-memory tree.  Kernel image limit 64 MiB (loaded at 2 MiB by ATA PIO, stack at 0x90000; the heap starts above the image, capped at 32 MiB); the boot disk must be IDE-compatible (QEMU default); the boot stage handles at most 20 E820 entries.

## KCFS 2: a mature file system (1.0)

- **Crash-safe store** (`kernel/kcfs.kc`): two alternating slots, each with a header (generation, size, node count, CRC-32 of the data, header CRC-32). A save writes the *other* slot's data first and its header last (the commit), so a power cut at any point leaves the previous generation intact. On boot the newest slot with a valid CRC wins; if it is damaged the older generation is loaded (`fs_recovered = 1`, shown in `df`). Old KCFS 1 images are migrated automatically.
- **Autosave**: changes are written 3 s after the first edit (retry after 10 s on I/O errors), and always flushed on restart / shutdown. `sync` still forces a save and prints the generation.
- **Metadata**: creation and modification times (wall clock, from the RTC) and attributes (read-only `r`, hidden `h`, system `s`), persisted on disk. Read-only items refuse write, delete, rename and move.
- **Operations** (`kernel/fs.kc`): rename, move, recursive copy, unique "x copy" names, recursive delete (refuses as a whole if anything inside is read-only), sorted listing (folders first, case-insensitive), `fs_fsck` (orphans go to /lost+found, duplicate names are renamed, bad sizes and nodes repaired; also run on every load).
- **Files app**: sorted list with modified dates and R/H flags, rename (`r` or Ren), Copy / Cut / Paste (`c` `x` `v`), Lock (read-only) and Hide, `.` toggles hidden items, folder delete needs a second press, details panel (created/modified/size), Saved / Unsaved indicator.
- **Shell**: `ls [-la]`, `stat`, `attr +r|-r|+h|-h` (alias `chmod`), `fsck [-r]`, richer `df`, `mv` rename/move via the new primitives.
- **Capacity**: 2048 nodes; the store is 1.75 MiB per slot (two slots), names up to 27 characters.
- Tests: `make host-test-fs` (CRC, time, round trip, power cuts at both stages, corrupt slot fallback, legacy migration, attributes, rename/move/copy, fsck, autosave, capacity) and `make host-test-files` (Files app). Not yet run in real QEMU/hardware.

## Kernel threads (1.1)

`kernel/threads.kc` adds real kernel threads (before 1.1 the OS was one polled loop).
- **Context switch**: 15 bytes of machine code (push rbp/rbx/r12-r15, swap rsp, pop, ret) built at boot and called through `callp()`; every thread has its own 32 KiB stack, pre-filled with a pattern so the scheduler detects an overflow (bottom 64 bytes changed: the thread is stopped and logged) and `ps` shows the stack high-water mark.
- **Scheduler**: cooperative (a thread runs until it yields, sleeps, blocks or exits; the desktop yields once per frame). Priorities 0-3, round robin within a level, aging (+1 step per 4 passes) so low-priority threads never starve. Slices over 200 ms are counted as overruns. Per-thread CPU%, switches and idle time are accounted.
- **API**: `thr_create(name, fnaddr(f), arg, prio, flags)`, `thr_yield`, `thr_sleep(ms)`, `thr_exit`, `thr_join(id, timeout)`, `thr_kill(id)`, `thr_set_prio`; mutexes (recursive, released automatically when the owner dies), counting semaphores and 32-slot message queues, all with timeouts.
- **Autosave thread**: the file-system saver is now a background thread; `fs_save` writes in 64-sector chunks and yields between them (no UI freeze), holds the `fs` mutex so only one save runs, and an edit made while a save is in flight keeps the tree dirty.
- **Tools**: Monitor has a *Threads* tab (state, priority, CPU bars, stack use, kill button, CPU history); terminal commands `ps`, `kill <id>`, `spawn counter|spin|hog [n]`.
- Test: `make host-test-threads` runs the real context switch natively on the host (round robin, sleep, priorities, aging, mutex, semaphore, queues, stack canary, registers preserved, table full, background save). Not yet run in QEMU/real hardware.

## 1.5 - RAM, resolution and a stronger boot stage
- **120 MiB heap.** The kernel heap cap went from 32 MiB to 120 MiB (`HEAP_MAX` in kernel/mm.kc). Run QEMU with `-m 128` (the Makefile already does).
- **Higher resolutions.** The 1280-pixel limits are gone (kernel accepts up to 4096x2400; wallpaper tables are allocated per load). New kernel/display.kc drives the Bochs/QEMU VGA "DISPI" registers, so the screen can change live without a BIOS call:
  Appearance has a **Display** row (1024x768 / 1280x800 / 1600x900 / 1920x1080 / 2560x1440; sizes that do not fit video memory are greyed). The choice is saved in `/etc/display`; with nothing saved the desktop moves up to 1920x1080 on its own. Real hardware without DISPI keeps the mode chosen by the boot stage (which now accepts modes up to 1920x1200).
- **Boot stage ("BIOS") hardening** (boot/boot.kc):
  - stage 1 checks for INT 13h extensions, retries each read 3 times with a controller reset, prints the BIOS error code, and verifies a stage-2 signature;
  - stage 2 checks the CPU for long mode and SSE2 (clear message instead of a crash), enables A20 by INT 15h, then the fast gate, then the keyboard controller, verifying each with a wrap-around test;
  - memory map falls back from E820 to E801, to INT 15h AH=88h, to a fixed 15 MiB assumption;
  - the kernel image is checksummed after loading (mkimage stores a 32-bit dword sum at image offset 2552); a damaged image stops with `CRC!` instead of running garbage.
  `make boot-sim` now covers all of these paths (A20 methods, CPU failures, E820/E801/88h fallbacks, disk retries, bad signature, flipped kernel bit, full-HD mode accepted).
- QEMU: `qemu-system-x86_64 -drive format=raw,file=peacock.img -m 128 -vga std -nic user,model=rtl8139`

## 1.6 - Notes 2 (kernel/notepad.kc)
A real text editor replaces the old Notes: **selection** (Shift+movement, mouse drag, double-click word, triple-click/gutter line, Ctrl+A), **clipboard** (Ctrl+X/C/V; copy/cut without a selection takes the line), **undo/redo** (Ctrl+Z/Y, typing runs grouped, history of ~2000 edits), **find / replace / replace all** (Ctrl+F, Ctrl+R; live match count, case toggle, replace-all is one undo step), **go to line** (Ctrl+G), **word wrap** (Ctrl+W) and **line numbers** (Ctrl+L), tab stops, auto-indent, Tab/Shift+Tab block indent, Ctrl+D duplicate line, Ctrl+K delete line, Alt+Up/Down move line, word-wise Ctrl+Left/Right/Backspace/Delete, Home toggles first-non-blank, scrollbar and mouse wheel (PS/2 IntelliMouse is now detected).
Files: New/Open/Save/Save as prompts, CRLF files are detected and written back as CRLF, binary / read-only / oversized files open read-only, the title shows `*` when modified, closing or replacing a modified buffer asks first, and unsaved text is mirrored to `/home/.notes-recovery` every 10 s and restored after a crash.
Other: the keyboard driver now tracks Alt (`kb_alt`) and right Ctrl; `make host-test-notes` has 60+ checks. `make` no longer passes `--map` to kcc by default (it ran out of memory on the bigger kernel); use `make MAP=1` if you want the map. The kernel is 1937 of ~2043 sectors that fit before the data store, so further growth will need the store moved.

## 1.8 - USB, Settings, a quieter desktop
* **USB** (`kernel/usb.kc`, hardware access in `kernel/usbhw.kc`): a polled UHCI (USB 1.1) host controller driver, found by PCI class 0C03/00 (QEMU: `-usb`). It resets the controller, enumerates the two root ports (reset, address, descriptors, configuration) and notices plug / unplug while running. Supported devices: HID boot **keyboard** (with auto-repeat, Shift/Ctrl/Alt/Caps), HID **mouse** and **absolute tablet** (`-device usb-tablet` gives a pointer without grabbing), and bulk-only **mass storage** (INQUIRY, READ CAPACITY, READ(10): read-only raw sector access). No hubs, no isochronous, no EHCI/xHCI-only machines.
  Terminal: `usb` lists devices, `usb read <sector>` dumps 128 bytes of a sector of the first USB disk.
* **Settings** (`kernel/settings.kc`): one window with a sidebar: Appearance, Fonts, Network, USB, System. Appearance, Fonts and System Info are no longer separate apps (`open info|fonts|appearance` and the top-bar network pill open the matching Settings page).
* **Root window**: the desktop now shows only Files, Browser, Terminal, Notes and Settings. The launcher lists the other apps (14 in all; `app_hidden()` removes the merged ones).
* Tests: `make host-test-usb` runs the driver against a simulated UHCI controller (`tests/host/usb_host.kc`) with a keyboard, tablet, mouse and a 64 KiB disk, including hot-plug. Real QEMU / hardware behaviour of the driver is untested here.
* Kernel is now 2020 sectors; the file store starts at LBA 2048, so only ~23 sectors of headroom remain before the image layout must move.
* QEMU: `-m 128 -vga std -nic user,model=rtl8139 -usb -device usb-tablet -device usb-kbd` (add `-drive if=none,id=u,file=disk.img,format=raw -device usb-storage,drive=u` for a USB disk).

## 1.8.1 - smoother Terminal
Profiling (tests/host/harness_bench.kc) showed the Terminal's frosted backdrop was re-blurred for the whole window on every mouse move over it (14 ms per frame in the host build, vs ~1.4 ms for other windows). Now: the blurred backdrop is cached while only the cursor moves or the Terminal's own text changes (`dmg_add_cur`, `term_glass_ok`), dragging the Terminal skips the blur, and typing repaints one line instead of the whole window. Host timings per frame: mouse over Terminal 14 -> 1.5 ms, typing 10.7 -> 2 ms, dragging 14.5 -> 6 ms.

## 1.9 - 64-bit pixel pipeline, PCI bus, ACPI and hardware control
* **64 bits per pixel**: the back buffer is now 64-bit RGBA16 (`bb: *u64`, 16 bits per channel; `p64`, `px32`, `mixp`, `mixpp` in gfx.kc). Alpha blending, glass panels, window fades, SVG and text anti-aliasing all blend at 16-bit precision; the flush to the screen dithers down with a 4x4 ordered dither (exact colours bypass it). **The screen itself is still 24/32 bpp: no display hardware scans out 64 bpp.** Costs: 8 bytes per pixel (a 1080p buffer is 16 MiB; the display selector now also checks free heap, `disp_heap_ok`), and compositing is roughly 1.4x slower in the host benchmark.
* **PCI** (`kernel/pci.kc`): full bus enumeration through bridges and multi-function devices, BAR sizing (I/O, 32-bit and 64-bit memory, prefetchable), capability lists (PM, MSI, MSI-X, PCIe, AGP), 8/16/32-bit config access, `pci_enable` (I/O, memory, bus master; wakes D1-D3 devices, unmasks INTx), `pci_find` / `pci_find_class`, vendor/device/class names, and the driver that owns each device. The RTL8139 and UHCI drivers now find and enable their hardware through it.
* **Hardware control** (`kernel/hwctl.kc`): ACPI (RSDP, RSDT/XSDT, FADT, MADT, DSDT `_S5`), real ACPI soft-off with the SMI enable handshake, reset through the ACPI reset register then the PCI reset port, CPU identification (vendor, brand, family/model/stepping, features). `poweroff` and `reboot` use them and fall back to the QEMU/Bochs ports.
* **Terminal**: `lspci [-v]`, `lscpu`, `lsmem`, `acpi`. **Settings**: new Devices page. The kernel is now 2108 sectors, so the file store moved to LBA 3072 and the image is 17 MiB.
* Tests: `make host-test-hw` (simulated 7-function PCI tree with a bridge and a 64-bit BAR, synthetic ACPI tables); all earlier suites updated for the 64-bit buffer. Not verified on real hardware or in QEMU.
